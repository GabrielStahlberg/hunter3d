# Stahlberg Labs Design System

## Philosophy

Stahlberg Labs websites share engineering and design discipline, not identical visual appearance.

Every client must retain an individual visual identity.

## Spacing

Prefer a consistent spacing scale.

Avoid arbitrary spacing values.

## Typography

Every project should define:

- display
- H1
- H2
- H3
- body
- small
- caption

Typography must provide clear hierarchy.

## Colors

Define semantic design tokens rather than using raw colors throughout components.

Examples:

- background
- foreground
- primary
- primary-foreground
- secondary
- muted
- accent
- border
- destructive

## Containers

Use consistent content widths.

Avoid sections with unrelated horizontal alignment.

## Sections

Maintain consistent vertical rhythm between major page sections.

## Components

Reusable components should expose variants rather than duplicate markup.

## Buttons

Always distinguish:

- primary action
- secondary action
- tertiary/text action

Avoid having multiple competing primary CTAs in the same visual area.

## Cards

Use cards only when grouping content improves comprehension.

Do not automatically wrap every piece of content inside a card.

## Radius

Choose a radius personality per brand.

Examples:

- sharp
- subtle
- soft

Do not randomly mix radius styles.

## Shadows

Use shadows sparingly.

Depth must communicate hierarchy rather than decoration.

## Motion

Animations should:

- provide feedback
- clarify hierarchy
- support storytelling

Avoid animation solely because it looks impressive.

Respect reduced-motion preferences.

## Responsive design

Components must be designed mobile-first.

Desktop layouts must not simply collapse badly into mobile layouts.

## Accessibility

Visual design must preserve:

- contrast
- readable text
- visible focus
- understandable controls
- usable touch targets
